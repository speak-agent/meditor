# 工作区切换与任务生命周期

GUI 与 `meditor serve --stdio` 共用应用内核中的工作区切换操作。切换不创建新的应用会话，也不改变编辑器设置、工具目录或运行时数据目录；每次成功切换递增工作区 generation。

- `workspace.canLeave` 返回 `canLeave`、`generation`、`unsavedDocuments` 和 `runningTasks`，供离开前提示使用。
- `workspace.switch` 接收目录 `path` 和读取到的 `generation`。目录可为绝对路径或相对当前工作区的路径；只在本机命令中使用，返回结果不包含绝对目录。
- 同目录选择是无副作用操作。其他目录必须存在、可读取且确为目录；在提交切换时再次检查未保存文档、运行中的任务与 generation。检查失败保留原工程和编辑内容。
- 目标目录的文件列表在提交前准备；成功结果包含 `listing`，GUI 不需要先清空旧列表再查询。文件列表沿用现有 3000 项上限和目录过滤规则。
- 成功切换清除旧文档及已结束任务，停止原 LSP，并重置工程信任。文档和任务编号在同一应用会话中持续递增，旧编号不能别名到新工程对象。
- 所有应用命令结果附带 `workspaceGeneration`。请求可带同名字段；不匹配时以 `workspace-conflict` 拒绝，避免异步调用误用新工程上下文。跨进程共享正在编辑的 GUI 会话仍未实现。

GUI 在打开目录选择器前检查离开条件，并在结果返回后通过上述内核操作重新检查。一次只允许一个目录选择请求，取消或异常会恢复入口；旧文件授权在切换成功后才替换。可注入的 `WorkspaceServices` 目录选择边界供宿主集成及无窗口异步回归使用，默认仍采用 HuxerUI 系统选择器。

构建、运行、测试任务提供取消按钮。轮询捕获应用对象和 generation，旧工作区续体不能覆盖新工程输出和状态。关闭窗口同样检查未保存文档及活动任务；用户先保存或取消任务后再关闭。

验证范围：内核测试覆盖未保存保护、相同目录、缺失目录、文件冒充目录、中文路径、信任重置、旧文档及过期 generation。GUI 虚拟时钟测试覆盖选择目录期间编辑、脏文档预检查、选择取消、选择器异常、无效目标及成功切换。CLI 测试使用真实子进程和 LSP 协议夹具，覆盖任务取消、运行时切换拦截、LSP 停止、旧文档/任务编号失效和工具目录不变。

这部分不等于四端产品验收。尚未实现保存/放弃/取消对话框、崩溃恢复、工程恢复与 GUI/CLI 跨进程连接；系统目录选择器、原生关闭流程及移动端文件授权还需要各平台实际验证。目录枚举仍是同步且有上限，后台扫描和大工程性能证据另行补齐。

Windows 首轮 CI 暴露了中文工作区错误路径中的本地编码转换：错误脱敏原先调用 `path.string()`。现统一以 native UTF-8 与 generic UTF-8 形式匹配工作区路径，避免错误处理再次因本地代码页转换而抛出；平台测试新增中文目录的普通错误、两种分隔符路径脱敏用例，完整 CI 继续验证。
