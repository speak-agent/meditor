# UTF-8 BOM 与换行格式保留

状态：A03/A04 的部分实现，尚不能据此宣布数据完整性、原生输入或四端产品验收完成。

## 数据与坐标契约

文档内核继续保存原始 UTF-8 字节。`document.read`、CLI 字节编辑、保存冲突比较和撤销历史都保留 BOM 与 LF/CRLF，没有把现有机器协议悄悄改为规范化文本。文档摘要新增 `format`：`encoding: utf-8`、`bom`、`lineEnding: lf|crlf`、`mixedLineEndings`、`loneCarriageReturns` 和 `lineBreaks`。`lineEnding` 取当前第一个 LF/CRLF；当前打开记录变成无换行文本时保留上次偏好，新打开且无换行的文件默认 LF。它不是已经实现的跨重启格式偏好持久化。

`TextPresentation` 是文档包公共接口的一部分，提供不可变原始/显示快照及显示字节到原始字节的映射。显示侧隐藏文件开头的一个 UTF-8 BOM，把 CRLF 视为一个 LF；UTF-8 中间字节不是合法光标边界。原始文档位置和显示位置明确区分，未来 GUI 语言服务必须经过这一边界，不得把显示 UTF-16 偏移直接当原始字节或 LSP 坐标。

GUI 还维护每个换行符的样式。插入/粘贴的新换行采用当前偏好，删除和多操作批次保留未替换换行的原样式；native 输入批次先按原输入坐标完成校验，再将 CRLF 规范到显示坐标并调整 selection/composition。保留文本的 DeleteSurrounding 使用原换行元数据。组合输入基线同时保存文本、换行样式和 BOM 标志，取消能够恢复原始格式；失败批次不提交文档或格式的部分修改。GUI 新输入的单独 CR 按换行处理。

GUI 对已有单独 CR 控制字符的文件明确显示只读提示，仍允许选择/复制，避免把它与 CRLF 混淆后写坏原文；不宣称完整支持旧 Mac CR 文本或任意控制字符。CLI 仍可按原字节读取/编辑，保存原始契约不变。其他不支持的编码、二进制识别和完整只读查看体验仍需后续补齐。

桌面状态栏显示 UTF-8/BOM、LF/CRLF 与混合提示。基础高亮忽略 BOM 字符，但 `document.highlight` 的第一行 token 字节范围仍包含原始 BOM 前缀，CLI 与 GUI 不混用坐标。

## 验证路径

- 文档包：BOM/CRLF 映射边界、500 份 Unicode 混合换行的逐字节往返、非法 UTF-8 与不匹配元数据拒绝。
- GUI 核心：前后两处编辑的原换行保留、拒绝批次原子性、中文/emoji 与 native CRLF selection_after 转换、清空后继续输入、组合取消和新 BOM 回退、DeleteSurrounding 保留选中文本样式、单独 CR 只读。
- 真实 headless 工作台：手机/中等/桌面三个尺寸下 select-all、输入、保存、撤销与文件字节比较；桌面格式标签检查。
- CLI：原字节读取/编辑/保存和新增元数据；BOM 文件第一行高亮范围；独立源码/打包消费者调用新增公共接口，验证编译库的实现链接。
- Linux 原生窗口：驱动新增 BOM+CRLF 场景，真实键盘替换全文、Enter、保存和多次撤销，逐字节断言并保留合成截图。该场景加入 CI，不能替代 Windows/macOS 原生 GUI 或手机 IME 验收。
