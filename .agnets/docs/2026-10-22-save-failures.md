# 只读文件与保存失败保护

Linux 上已复现旧行为：目标文件设为 `0444` 后，目录仍可写，基于临时文件的替换可以覆盖只读文件，且文档错误地进入已保存状态。

平台写入现在先检查目标类型和写入权限。只读文件拒绝保存，POSIX 同时检查实际写入访问；Windows 用不截断文件的写句柄检查访问。目标不是普通文件时拒绝直接替换。目标权限位复制失败也必须中止，不能忽略后继续替换。应用将只读错误暴露为 `file-read-only`，GUI/CLI 共用，en/zh 有明确重试提示。

失败不能清除 dirty、改变缓冲内容或消费撤销/重做历史；只读拒绝不改原文件内容和修改时间，不留下临时文件。恢复写入权限后可按同一 revision 重试。外部重命名/删除继续由磁盘冲突检测拦截，不能静默重建旧文件。

验证包含：

- 应用内核中的只读拒绝、缓冲/revision/dirty、原文件及时间戳、恢复权限后重试、外部重命名。
- POSIX 上父目录不可写时临时文件创建失败，原文件与缓冲保留，权限恢复后重试。
- CLI JSONL 会话中得到稳定错误码，并在权限恢复后完成保存。
- 实际 GUI 视图树中，手机/桌面尺寸与 en/zh 错误反馈、原文件不变、Undo/Redo 后重试保存。

Linux 原生窗口测试还覆盖只读保存拒绝、失败后关闭窗口被拦截、恢复权限后保存及历史重放；合成截图保留错误反馈。该路径进入 Linux CI 的 BOM/CRLF 与查找替换场景。
