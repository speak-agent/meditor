# 后台语言查询接口

`language.query` 把语言服务初始化和 RPC 等待移到后台，供 GUI 与 Agent 使用。编辑器线程只准备不可变快照并提交；不在工作线程读取或修改工作区文档容器。多个查询共用同一个语言服务，既有同步查询也复用该服务。

这些命令需要持久的 `meditor --cli serve --stdio` 会话或 GUI 应用内核，文档 ID 与查询 ID 绑定会话，不作为一次性进程间的持久标识：

| 命令 | 输入和结果 |
| --- | --- |
| `language.query` | `document`、`revision`、`operation`，按操作携带 `position` 或 `name`；可选 `timeoutMs`。返回查询 ID 与状态 |
| `language.result` | `query`，返回状态、结果/错误、文档修订、generation、`stale` 和取消请求标记 |
| `language.cancel` | `query`，请求取消；已经完成的查询保留完成结果 |
| `language.stop` | 取消全部查询及初始化，释放语言服务；旧查询 ID 失效 |

操作包括 completion、hover、definition、references、symbols、signature、diagnostics，以及 modules.graph、modules.info、modules.contexts。参数 schema 包含操作枚举、UTF-16 位置和条件必需字段；查询必须绑定当前 C++ 文档修订，并先经过工程信任检查。完整能力、数量和时间边界见 `capabilities.asyncLanguage`。

结果绑定提交时的全部已打开文档修订与集合；期间编辑、撤销、打开其他文档等会使结果标记 `stale`。调用方只应使用成功且未过期的结果。模块查询同步当前已打开 C++ 文档的快照；后端原有位置数据和实际工程文件变动仍需结合具体功能适配，不能把这个标记当作完整文件系统快照保证。

诊断结果另外包含 `versionVerified` 与预期 LSP 版本。服务端携带版本时等待对应版本；缺少版本时明确标记未验证，不假设旧缓存就是当前诊断。未验证数据不能冒充已确认的当前文本装饰。

输入快照总量限制 64 MiB，同时最多 8 个查询，保留最近最多 16 个查询；优先回收最早的已完成查询。保留结果按序列化字节数累计限制 64 MiB。它们是逻辑数据边界，不是整个进程的堆内存上限。取消结束指定查询；停止、撤销信任和切换工作区会清理对应任务；ID 在同一应用中持续递增，不别名到新工作区查询。

保存不等待后台初始化。语言文档同步有独立锁和递增版本，拒绝旧快照把服务端文档倒退；保存遇到语言同步繁忙时保留成功的文件结果并给出同步提示。启动失败有终态，可在后续查询重试。异步错误脱敏，过长服务端细节省略，短消息在 UTF-8 边界限制输出长度；失败不返回部分结果。

验证覆盖延迟初始化期间编辑/保存、旧修订拒绝、过期/当前结果、对应版本诊断、模块图、并发上限、取消、超时、初始化期间切换工程、停止后旧 ID 失效和合成敏感错误。真实固定版本工具测试覆盖后台符号/模块图/诊断，并通过未保存的错误文本和撤销验证诊断产生、清除及源文件未被隐式保存。

仍需完成 GUI 补全/诊断/跳转/图形视图及其端到端交互、位置映射、跨进程共享会话、原生平台故障与性能证据。快照复制、JSON 准备和部分同步仍有调用线程成本；既有同步命令保持兼容，GUI 不应以它们替代后台接口。测试中的秒级防挂死阈值不是产品输入延迟验收。外部文件变化、完整语言缓存预算和整个产品的 A05/A06/A09 继续保持未验收。
